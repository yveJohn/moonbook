# M6 全域迁移与对象核对验收

验收日期：2026-08-21

## 结论

`moonbook-migration-audit` 已从统计报告提升为统一只读退出门。源目标映射、全部 `all` Stage checkpoint、迁移错误、内容生产关联、MinIO 对象完整性和全域财务任一异常都会返回非零。报告不包含 DSN、Secret、对象键、业务 ID 或正文。

本报告关闭收敛计划 Task 6，不代表约 8 GB 完整副本已迁移。完整容量、耗时、吞吐、资源峰值和幂等重跑归 Task 7。

## 覆盖面

- `allMigrationStages` 成为 `all` 命令唯一 Stage 列表，覆盖测试与审计合同双向比较；新增或删除 Stage 未同步审计合同会失败。
- 内容映射覆盖论坛来源/板块/候选/导入任务/抓取日志、TXT、AI 配置/模型、章节清洗、章节摘要、作品画像和书籍合并血缘。
- 关联核对覆盖采集链路、TXT 目标书、AI 模型配置、清洗任务/结果/书籍/章节、画像书籍和合并任务/源目标书。
- 对象核对从活动引用、清洗原始/清洗对象、合并源/目标对象和 TXT 原文件流式取证，校验 kind、book/owner、MinIO Stat 字节/元数据哈希、实际字节和 SHA-256。
- 财务复用 `commerce/reconcile.Full`，覆盖钱包、不可变流水、充值/购买订单、支付回调、会员和权益。

## 脱敏与失败合同

- 对象和财务样本只输出 SHA-256 指纹，分别以对象类型/内部身份和财务 domain/key/field 生成；最多各 100 条。
- 对象错误稳定分类为缺失、读取失败、引用元数据、Stat 大小/哈希、内容大小/哈希差异。
- checkpoint 缺失/未完成、核对 SQL 执行失败和 migration error 不会被忽略。
- Long ID 只在进程内部以 `int64` 或十进制字符串处理，不进入样本明文。

## 真实故障注入

- 一次性 MySQL 8.4 开启 `read_only`，插入 ID `9007199254740993` 的源行；空 PostgreSQL 目标稳定报告行数和最大主键不足。
- PostgreSQL 17 临时库从 0 迁移到 70，注入断裂论坛板块关联和缺失 AI 模型表，分别报告业务关联与核对 SQL 失败。
- PostgreSQL + MinIO 注入正常对象、缺对象、错注册大小、错元数据哈希和错内容哈希，五类对象差异全部检出。
- 现有财务集成测试先证明夹具零差异，再移除已支付充值订单流水关联，`Full` 稳定报告异常。
- 所有临时 PostgreSQL 库、MinIO 测试前缀和一次性 MySQL 容器均已清理。

## 服务影响

- `server` 构建产物新增/更新两个迁移 CLI；应用 HTTP 和后台 Worker 运行时行为不变。
- 执行核对命令需要可读 MySQL/PostgreSQL/MinIO 连接配置；部署现有服务无需因本任务重启。
- PostgreSQL、Redis、MinIO、Web、Reader UI 和 Gateway 无代码变化，无需重启。
