# 管理端充值订单展示优化设计

## 1. 目标与范围

本次仅优化 Gin-Vue-Admin 管理前端的充值订单页面，不修改管理 API、数据库、Reader 接口或支付业务逻辑：

- 分页默认每页 10 条，仍允许管理员切换为 20 条或 50 条；
- 状态筛选、订单列表和详情抽屉统一显示简体中文；
- 列表创建时间统一显示为 `yyyy-MM-dd HH:mm:ss`。

## 2. 页面设计

充值状态在页面内维护统一的值与中文标签映射。筛选请求继续提交既有英文枚举，人工补单和主动同步的状态判断也继续使用英文枚举，避免改变后端契约与业务行为。

| 状态值 | 中文标签 |
| --- | --- |
| `creating` | 创建中 |
| `pending` | 待支付 |
| `gateway_unknown` | 网关状态未知 |
| `create_failed` | 创建失败 |
| `superseded` | 已替换 |
| `expired` | 已过期 |
| `callback_exception` | 回调异常 |
| `paid` | 已支付 |

接口出现映射表之外的状态时，页面保留原始状态值，避免未知状态被隐藏。状态为空时显示 `-`。

创建时间复用管理前端现有日期格式化工具，按浏览器本地时区展示到秒；时间为空时显示 `-`。本次只调整列表已有的“创建时间”字段，不扩展详情字段。

## 3. 数据流与兼容性

分页首次请求使用 `page=1&pageSize=10`。用户切换每页条数后仍由现有分页组件触发重新查询。

状态筛选组件使用中文标签展示、英文值查询。列表与详情只在渲染时把英文状态映射为中文，不改写接口响应对象。所有 Long ID 继续按字符串展示和提交。

## 4. 验证

新增页面源码级回归测试，至少固定以下行为：

- 默认分页大小为 10；
- 八种状态具有预期中文标签，筛选项仍使用英文值；
- 列表和详情均调用同一状态显示函数；
- 创建时间通过既有格式化工具输出，空值有明确占位。

完成后运行管理前端定向测试、lint 和生产构建。该变更只影响管理前端 Web 服务；部署后需要重新构建并重启 Web 服务，Server、Reader、PostgreSQL、Redis 和 MinIO 无需重启。
