# Reader 充值金额四位小数展示设计

## 1. 文档状态

- 日期：2026-08-28
- 状态：设计已获用户确认
- 范围：Reader 充值订单页金额展示与回归测试
- 影响服务：`reader-ui`

## 2. 目标

充值订单页的“需要支付”和“基础定价”统一显示四位小数：

- `2` 显示为 `2.0000`；
- `2.58` 显示为 `2.5800`；
- 当前历史数据中的 `2.00000000` 显示为 `2.0000`。

GM Pay 已由用户确认只会返回最多四位小数，因此 Reader 无需展示八位小数。

## 3. 实现边界

- 在 Reader 前端新增只处理十进制字符串的金额格式化逻辑，不将金额转换为 JavaScript
  `Number`，避免浮点误差；
- 同一格式化结果用于顶部“需要支付”和明细区“基础定价”；
- “需要支付”继续优先使用 `actualAmount`，缺失时回退 `priceUsdt`；
- 不修改 API DTO、后端金额、数据库字段、GM Pay 请求、支付回调或二维码内容；
- 不修改充值页其他布局、文案和交互。

## 4. 异常与兼容

- 对符合十进制格式的值补足或规范化为四位小数；
- 对历史八位值只允许第 5 位以后全为零，并去除多余零；
- 若接口意外返回超过四位且后续存在非零数字，保留原始字符串，不静默截断或四舍五入，
  避免展示错误的应付金额。

## 5. 测试与发布

- 组件测试覆盖实际应付金额和基础定价统一四位展示；
- 格式化测试覆盖整数、两位、四位、历史八位零尾数和异常高精度值；
- 执行 Reader 定向测试、完整测试和生产构建；
- 通过现有 `scripts/deploy-production.sh` 本地构建并发布，核对四个应用容器、迁移、
  公网 HTTPS 和 Server 错误日志。

## 6. 服务影响

- 代码仅影响 `reader-ui`；
- 现有生产发布脚本按固定发布单元重建 `server`、`web`、`reader-ui` 和 `gateway`；
- PostgreSQL、Redis、MinIO 和 GM Pay 无需重启。
