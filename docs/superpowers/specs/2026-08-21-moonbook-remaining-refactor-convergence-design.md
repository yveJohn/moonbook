# Moonbook 剩余重构收敛设计

日期：2026-08-21

状态：已批准，待实施

## 1. 背景与目标

Moonbook 已完成 M0 至 M3，M4 至 M7 已具备大部分业务实现和分散验证证据，但尚未达到生产切换就绪。剩余问题集中在管理基座最终验收、内容生产的本地闭环、完整数据副本迁移、监控与安全、统一发布验证和最终证据收敛。

本设计不替代以下既有权威文档：

- `docs/superpowers/specs/2026-08-14-moonbook-gin-vue-admin-refactor-design.md`；
- `docs/goal-mode/2026-08-14-moonbook-refactor-goal.md`；
- 根目录 `AGENTS.md`。

本设计负责把当前剩余工作收敛为 R1 至 R5 五个可独立验收的工作包。目标是完成所有本地可实现、可验证的事项，使仓库达到生产切换就绪，或仅剩必须由用户提供真实凭据、生产授权或商业授权才能完成的外部验收项。

未经用户单独授权，本目标不执行生产迁移、真实支付、生产 DNS 或反向代理变更、生产流量切换、生产数据写入或 `git push`。

## 2. 执行方案

采用按依赖和风险收敛的顺序：

1. R1 管理基座与平台任务监控；
2. R2 内容生产本地闭环；
3. R3 全量迁移与完整副本演练；
4. R4 生产就绪能力；
5. R5 固定提交最终验收。

当前未提交的平台任务监控实现属于 R1，必须在保留现有工作的基础上补齐验证并单独提交。只有后续工作不依赖当前缺口时，才允许在工作包之间交错处理。

每个工作包必须完成以下闭环：

1. 从当前代码、冻结旧项目、测试、数据库映射和证据文档审计事实；
2. 实现代码、数据库迁移、管理页面、配置和运维入口；
3. 执行定向单元测试、静态检查和构建；
4. 使用真实 PostgreSQL、Redis 和 MinIO 完成受影响的集成验证；
5. 按风险补充 HTTP 契约、浏览器、Compose、迁移、恢复、性能或安全验证；
6. 更新进度、功能矩阵、迁移映射和专项证据；
7. 检查整个 Git 工作区，排除产物、缓存、日志和敏感信息；
8. 按功能使用简体中文提交，提交后检查仓库状态。

不得通过删除测试、放宽断言、跳过必需门或使用 `continue-on-error` 获得通过结果。

## 3. 状态与证据管理

`docs/progress/refactor-status.md` 继续作为当前事实状态入口，并增加或持续维护：

- 当前工作包；
- 已满足的退出条件及直接证据；
- 当前失败或缺口；
- 下一项可执行工作；
- 仅能外部完成的验收项。

现有文档中的陈旧描述必须根据当前代码和固定提交证据修正。代码存在、历史提交通过或局部测试未失败，均不能单独证明当前里程碑完成。每条完成声明必须链接到代码、测试输出摘要、运行报告或提交。

`docs/verification/final-report.md` 只在 R5 固定验收提交上收敛为最终报告。在此之前不得把模板占位改写为无证据的“通过”。

## 4. R1：管理基座与平台任务监控

### 4.1 平台任务监控

完成 `platform_jobs` 和 `platform_job_attempts` 的统一只读管理入口：

- 按模块、任务类型、状态、租约 Worker 和时间范围分页筛选；
- 查看任务状态、可用时间、租约、尝试次数和脱敏后的最后错误；
- 查看 attempt 的序号、Worker、执行结果、错误和时间；
- 所有 Long ID 作为 JSON 字符串输出并在前端作为字符串传递；
- 平台入口只读，不直接重试、取消或修改业务任务；
- 人工状态变化继续通过各业务模块的服务和状态机完成；
- 管理路由使用 GVA JWT、Casbin 和操作边界；
- 错误信息不得包含 Token、Cookie、密钥、连接串、对象键或完整敏感正文。

现有 `00067`、`00068` 迁移必须核对空库、升级和重复执行语义，避免菜单或权限 ID 冲突造成静默错误。退出证据至少包括服务测试、迁移清单、真实 PostgreSQL 仓储测试、真实管理员 HTTP 验收、管理前端测试/构建和桌面/移动浏览器旅程。

### 4.2 GVA 管理基座

在同一固定提交上验证：

- 管理员登录、强制改密、JWT、注销和会话撤销；
- RBAC、Casbin 越权拒绝和数据权限；
- 管理员、角色、菜单、API、部门、岗位、字典和参数；
- 登录日志、操作日志、文件日志和定时任务；
- 系统配置只读白名单及 Secret 不回显、不写入；
- 平台任务列表和 attempt 审计。

对在线管理员状态、通知公告、通用 OSS 管理和 SMTP，必须从冻结旧库数据、旧页面、调用方和脱敏运行配置取得证据，并分别形成以下二选一结论：

1. 属于当前有效能力，纳入实现、迁移和验收；
2. 没有有效数据或业务调用，经记录后明确移出重构范围。

不允许继续保留“基线已盘点”或“待确认”作为 M7 最终状态。

## 5. R2：内容生产本地闭环

### 5.1 Secret 和外部请求

论坛 Cookie 不得继续以新明文值保存在 PostgreSQL。运行时配置应保存 Secret 引用或“已配置”状态，真实值由环境变量或受控 Secret 注入。历史明文数据的处理必须使用前向迁移或受控迁移工具，不在日志和报告中输出原值。

论坛、代理和 OpenAI 兼容请求必须具备：

- 显式启用开关；
- HTTP/HTTPS、主机、端口和重定向限制；
- 连接、读取和总超时；
- 有上限重试和退避；
- 业务幂等或结果唯一性；
- 脱敏请求、失败分类和审计；
- 本地 HTTP 替身或真实沙箱证据。

### 5.2 功能与恢复验收

完成论坛来源连接检查，并覆盖发现、候选、导入、TXT、合并、章节清洗、摘要和作品画像的统一重启恢复验收。验证至少包括：

- 应用停止时释放或等待租约；
- 应用重启后恢复到期租约和待处理任务；
- 配置重载不会产生两个并行 Worker；
- 重复执行不新增章节、对象、结果或业务事实；
- 有限重试耗尽后状态、attempt 和错误一致；
- 人工继续或重跑走业务状态机；
- MinIO 输入和输出均校验大小及 SHA-256；
- 清洗、摘要、画像和合并采用结果保持既有事务边界。

真实供应商凭据不是本地闭环的前置条件。缺少真实论坛、代理或 AI 凭据时，完成适配器、配置合同、本地替身和精确外部验收步骤。

## 6. R3：全量迁移与完整副本演练

### 6.1 自动核对范围

在执行完整副本前，核对器必须覆盖：

- 逐 stage、逐表源目标行数、主键范围、空值和枚举分布；
- 小说、分类、作者、章节、SEO 和内容来源关联；
- Reader 账号、邀请、书架、历史、点赞、反馈和偏好；
- 钱包、不可变流水、奖励、订单、支付回调、会员和权益；
- 论坛来源、板块、候选、导入任务和抓取日志；
- TXT 原文件、导入任务和章节结果；
- AI 配置、模型、章节清洗、摘要、作品画像和书籍合并血缘；
- MinIO 对象数量、总字节、业务引用、大小和 SHA-256；
- `migration_checkpoints`、`migration_errors` 和未处理转换结论。

财务必须零差异。对象缺失、哈希错误、不可解释行数差异、关联断裂或静默丢弃均阻止通过。

### 6.2 完整副本演练

约 8 GB 候选副本只能在明确的本项目隔离目录、容器、网络和命名卷中使用。演练顺序为：

1. 校验备份文件大小、格式和 SHA-256；
2. 恢复只读旧 MySQL 副本并执行容量盘点；
3. 从空 PostgreSQL 和空 MinIO 执行全部版本迁移；
4. 运行所有业务迁移 stage；
5. 执行全域、财务和对象核对；
6. 从已完成状态重复运行，证明 `applied=0` 或业务结果不增长；
7. 记录各 stage 行数、错误、耗时、吞吐和峰值资源；
8. 生成 12 小时窗口、安全余量和最晚回退时间输入。

不得直接修改冻结旧项目或候选备份。不得用 MySQL 客户端绕过迁移工具写入目标 PostgreSQL。清理隔离数据卷前必须证明其只属于本次演练。

## 7. R4：生产就绪能力

### 7.1 监控和告警

根 Compose 增加可选 `monitoring` profile，包含 Prometheus、Alertmanager、PostgreSQL exporter、Redis exporter、cAdvisor 和 Blackbox Exporter；MinIO 使用原生 Prometheus 指标，Gateway 与 Reader SSR 使用黑盒探测和应用已有指标。告警覆盖：

- API 和 Reader 错误率、p95/p99 延迟和在途请求；
- PostgreSQL 连接、锁、慢查询和容量；
- Redis 可用性、内存和命中；
- MinIO 请求错误、容量和离线盘；
- 支付失败、回调拒绝和审计滞留；
- 任务积压、失败、重试耗尽和租约过期；
- 迁移错误、财务差异和对象校验失败；
- 容器重启、CPU、内存和磁盘水位。

Alertmanager 提供本地 UI 和通用 Webhook，生产通知地址继续由 Secret 或环境变量注入。每类关键告警必须有分级、阈值、静默/升级策略和故障处理入口。

### 7.2 安全和供应链

对 Go、管理前端、冻结 Reader 和最终容器镜像执行固定版本的依赖及漏洞扫描，生成 SBOM 和许可证清单。处理规则为：

- 有兼容修复版本的 high/critical 漏洞应升级并回归；
- 无法升级的冻结 Reader 漏洞必须给出具体缓解、影响和用户批准记录；
- GVA BSL 1.1 Production Use 商业授权作为外部 Go/No-Go 证据；
- 管理 RBAC、暴力登录、限流、安全响应头、敏感日志和 Secret 注入必须有自动化或运行证据；
- PostgreSQL、Redis 和 MinIO 使用最小权限凭据并记录轮换流程。

### 7.3 统一验证与运维

建立覆盖 M0 至 M7 的统一验证入口，在固定提交上编排：

- Go 格式、vet、race、模块边界和业务测试；
- 管理前端测试、ESLint、生产构建和供应链检查；
- 冻结 Reader 源树差异、536 项测试、生产构建和契约；
- 真实 PostgreSQL、Redis、MinIO 业务集成；
- MySQL 到 PostgreSQL/MinIO 迁移；
- 管理与 Reader 浏览器旅程；
- 空库迁移、备份恢复、升级回退、性能和安全报告。

耗时较长或需要 Docker 的门可以分 job 执行，但必须由一个最终入口汇总，任一必需门失败时整体失败。

Runbook 必须补齐 TLS 终止和可信代理、镜像 tag/digest、资源限制、日志轮转、磁盘水位、协调停写、支付回调处置、升级观察阈值、RTO/RPO、切换阶段时限、Go/No-Go 和最晚回退时间。

## 8. R5：固定提交最终验收

R5 选择一个已提交且工作区干净的 commit，执行全部可自动化验收。最终报告必须记录：

- 新仓库 commit、GVA 固定 commit 和旧仓库冻结 commit；
- M0 至 M7 每个完成判据及直接证据；
- 单元、race、集成、契约、SSR、E2E、迁移、性能、安全、备份恢复结果；
- 完整副本迁移行数、财务、对象和耗时结论；
- 所有功能提交；
- 受影响服务和各环境重启要求；
- 未执行的生产动作；
- 仍需用户提供的真实凭据、商业授权或生产操作授权；
- 正式切换、Go/No-Go 和回退 Runbook 入口。

只有以下条件同时满足，才能声明“生产切换就绪”：

1. R1 至 R4 的本地交付物和验证全部通过；
2. 管理功能矩阵没有未解释缺口；
3. 已定位的完整副本候选完成至少一次全量演练并通过财务、关联和对象核对；
4. 工作区除明确忽略内容外干净；
5. 剩余事项全部需要真实第三方凭据、商业授权或生产权限；
6. 最终报告不含无解释的“待完成”“待审计”或模板占位。

“生产切换就绪”不等于已经完成生产迁移或流量切换。

## 9. 错误处理和安全边界

- 数据迁移、财务、支付、对象存储和备份操作默认失败关闭；
- 发现不明差异时停止对应阶段，不自动修正业务数据；
- PostgreSQL 结构只通过更高版本前向迁移修改，已执行迁移不修改、改名或删除；
- MinIO 对象必须在 PostgreSQL 建立引用前验证大小和 SHA-256；
- Redis 不保存唯一业务事实；
- 所有 JavaScript Long ID 作为字符串处理，禁止 `Number`、`parseInt`、`el-input-number` 或算术转换；
- 外部响应、数据库错误和对象错误对外脱敏，内部通过低基数错误码和追踪 ID 审计；
- 生产凭据、Token、Cookie、密钥和完整敏感正文不得进入 Git、日志、测试快照或报告。

## 10. 测试和服务影响

验证顺序按风险递增：

1. 单元测试、静态检查和前端测试；
2. 真实 PostgreSQL、Redis 和 MinIO 集成；
3. HTTP 契约和权限；
4. 桌面与移动浏览器旅程；
5. Compose、迁移、恢复、性能和安全验收；
6. R5 固定提交统一复跑。

每个功能提交和进度报告必须说明影响的服务及重启要求：

- Go 代码或运行配置变化：重建并重启 Server；
- PostgreSQL 迁移变化：先运行一次性 migrate，再重启依赖新结构的 Server；
- 管理前端变化：重建并重启 Web；
- Reader 变化：重建并重启 Reader UI；
- Gateway、Compose 或监控变化：按变更重建对应服务；
- 仅文档变化：不影响服务，无需重启。

## 11. 外部验收清单格式

每个不能在本地完成的外部事项必须记录：

- 所需责任人和授权；
- 所需凭据或输入，但不记录真实秘密；
- 精确命令或操作入口；
- 前置备份和安全限制；
- 预期输出和通过判据；
- 失败风险、停止条件和恢复方式；
- 证据保存位置。

不得用本地替身结果宣称真实支付、真实供应商、商业授权或生产切换已经通过。
