# Moonbook M3 读者域与零修改兼容设计

## 1. 文档状态

- 日期：2026-08-14
- 状态：设计已获用户确认，书面规格待复核
- 所属里程碑：M3 读者域与零修改兼容
- 实现范围：读者身份与个人数据、公开书目和章节读取、公开 SEO、兼容路由与旧数据迁移
- 延后范围：钱包、流水、订单、购买、充值、支付回调和交易管理写流程，统一在 M4 完成

本文是总体重构设计的 M3 补充规格。若本文与根目录 `AGENTS.md`、目标文档或总体设计冲突，以约束更严格者为准。

## 2. 背景与目标

M2 已完成小说分类、作者、书籍、章节、MinIO 正文和读者 SEO 管理闭环，但尚未提供冻结 `reader-ui` 使用的 `/reader/**` 接口。M3 的目标是让冻结 Reader 无业务代码修改接入新 Go 后端，并迁移读者账号、密码摘要和个人阅读数据。

章节目录和正文响应包含商品、定价和权益结果。为避免 M3 返回错误访问状态，又不提前实现 M4 的交易写流程，本阶段同时建立 `commerce` 模块拥有的最小规范商品、定价和权益读取模型。M4 在同一模型上继续实现钱包、订单、购买和支付，不进行临时表到正式表的二次迁移。

M3 完成后，冻结 Reader 应能够完成公开浏览、注册登录、阅读、书架、点赞、历史、偏好和反馈旅程；历史有效权益应得到与旧系统一致的章节访问结果。

## 3. 方案选择

采用稳定模块所有权与窄接口组合方案：

- `reader` 拥有读者账号、认证、书架、历史、偏好、点赞、反馈、兼容 HTTP 和专用 DTO；
- `novel` 拥有公开书目、章节、SEO 配置和已校验正文读取；
- `commerce` 从 M3 起拥有商品、定价、会员和权益规范表，并提供只读访问判定接口；
- 兼容应用服务只通过模块公开合同组合数据，禁止跨模块直接操作内部表。

未采用的方案：

- 在 `reader` 建立临时权益投影表：会在 M4 引入二次迁移和所有权调整；
- M3 暂不迁移权益：会错误拒绝历史已购内容，无法满足零修改兼容；
- 临时放行付费内容：改变安全和商业规则，不可接受。

## 4. 模块与组件

### 4.1 Reader 兼容 HTTP

`server/internal/modules/reader` 下建立独立兼容路由、鉴权中间件、响应器和 DTO。管理端 GVA 响应、管理员鉴权对象及内部数据库模型不得出现在 Reader API。

兼容层负责：

- 绑定和校验路径、查询、Header 与请求体；
- 解析可选或强制读者身份；
- 调用应用服务并转换专用 DTO；
- 输出冻结契约要求的 JSON、分页或原始文本/XML；
- 将内部错误转换为稳定业务码和消息。

### 4.2 Reader 领域服务

Reader 内部分为身份、个人阅读和反馈三个边界：

- 身份：注册、登录、退出、资料、密码升级、会话撤销和账号状态；
- 个人阅读：书架、点赞、阅读历史和阅读偏好；
- 反馈：提交、分页查询及读者数据隔离。

这些边界可以拆分实施和测试，但共用读者 ID、时间和兼容 DTO 规则。任何 bigint ID 面向 JavaScript 时均输出十进制字符串。

### 4.3 Novel 公开读取合同

Novel 提供只读合同，返回已发布书籍、启用章节、分类、副分类、SEO 配置和正文内容。合同内部负责发布状态、软删除和对象引用约束，Reader 不直接查询 Novel 表。

正文读取必须通过现有版本化对象引用取得当前 MinIO 对象，并再次校验大小和 SHA-256。返回前按冻结旧实现规范化 UTF-8 纯文本，不暴露 Bucket、对象键或内部地址。

### 4.4 Commerce 访问合同

Commerce 提供批量 `AccessReader` 合同，输入读者、书籍和章节，输出：

- 商品及销售状态；
- 章节报价；
- 有效会员状态；
- 整书和章节权益；
- `readable`、`accessReason` 和 `purchasable` 决策。

目录读取必须批量加载上下文，不能逐章查询。M3 只开放查询和迁移写入边界；购买、扣款、发放权益及支付状态机留在 M4。

## 5. 数据模型

M3 通过新的前向迁移新增正式表，不修改 `00001` 至 `00011`。Reader 表固定为 `reader_accounts`、`reader_sessions`、`reader_bookshelf_entries`、`reader_book_likes`、`reader_reading_history`、`reader_reading_preferences` 和 `reader_feedback`；Commerce 表固定为 `commerce_products`、`commerce_chapter_pricing_config`、`commerce_membership_grants` 和 `commerce_entitlements`。

### 5.1 Reader 规范事实

- 读者账号：旧 ID、用户名、昵称、密码摘要及算法、状态、摘要升级时间和审计时间；
- 读者会话：只保存可撤销会话的安全摘要、有效期和撤销状态，不保存明文 Token；
- 书架：读者与书籍唯一关系；
- 点赞：读者与书籍唯一关系，并与书籍点赞汇总保持事务一致；
- 阅读历史：读者与书籍唯一当前进度，保存章节、位置、百分比和最后阅读时间；
- 阅读偏好：每名读者单例，枚举和默认值与冻结类型一致；
- 反馈：内容、状态、回复和时间，查询必须按读者隔离。

### 5.2 Commerce 最小规范事实

- 商品：类型、目标、名称、币值价格、奖励币规则、期限、销售状态和排序；
- 章节定价配置：字数单位与币值单位；
- 会员授予：有效期、永久标志和来源引用；
- 权益：读者、权益类型、目标、有效期、状态和来源引用。

商品与权益表从创建起即是 M4 延续使用的正式事实表。来源订单可为空以容纳历史迁移，但必须保留来源类型和旧引用，M4 不得把这些记录复制到另一组表。

### 5.3 ID、时间与约束

- 所有旧业务 ID 原值迁移为 PostgreSQL `bigint`，序列推进到最大值之后；
- JSON 中的 ID 和币值优先使用十进制字符串；
- 时间保存为 `timestamptz`，响应格式按冻结旧实现逐字段固化；
- 唯一关系、状态枚举、进度范围和跨实体关联由数据库约束与服务校验共同保证；
- Redis 只保存限流、短期会话辅助和可重建缓存，不保存唯一业务事实。

## 6. 鉴权与密码

公开内容接口使用可选读者鉴权，个人接口使用强制读者鉴权：

- 无 `Authorization`：公开接口按匿名处理；
- 有效读者 Token：注入读者 ID 并实时检查账号状态；
- 无效、伪造、过期或撤销的读者 Token：返回兼容未登录响应；
- 有效 GVA 管理员 Token：不能获得读者身份，公开接口按匿名处理，个人接口按未登录处理。

正式切换不接受旧 Token。旧密码摘要原值迁移，登录时按已识别的旧算法验证；首次成功后使用新算法生成摘要并在同一事务安全替换。未知摘要格式、错误密码和禁用账号均不得触发升级。日志和迁移错误不得记录密码或摘要全文。

新 Token 延续冻结 Reader 使用的 `Authorization: Bearer <accessToken>` 方式。Token 中只放最小身份声明；服务端会话摘要支持退出、改密和禁用账号后撤销。密码修改撤销该读者除当前响应流程外的所有现有会话。

注册和登录同时执行 IP 与账号维度限流，限流状态存 Redis。Redis 不可用时注册和登录失败关闭并返回兼容服务不可用错误，同时记录指标；不能静默取消限流后继续接受认证尝试。已建立会话仍以 PostgreSQL 会话事实和账号状态完成校验，不因缓存丢失而失效。

## 7. 公开内容与访问判定

### 7.1 书目与分类

公开书目只返回已发布且未删除的书籍。精选、分页、随机、分类、副分类和详情保持冻结排序、筛选、空值及分页结构。详情中的点赞、书架和历史字段由可选读者身份决定，匿名时返回冻结契约规定的默认值。

公开目录可以使用带版本前缀和 TTL 的 Redis 缓存。缓存键必须包含影响响应的筛选与排序参数；写操作提交后失效相关键。Redis 清空后 PostgreSQL 查询仍必须返回正确结果。

### 7.2 访问矩阵

收费模式固定为：

```text
word_charge
membership_only
login_free
fixed_price
```

访问原因固定为：

```text
login_required
book_owned
chapter_owned
membership
login_free
membership_required
book_purchase_required
chapter_purchase_required
free_chapter
unsupported_mode
```

判定顺序保持旧实现：匿名读者对任何受支持模式均先得到 `login_required`；登录读者的整书权益、章节权益优先于未知收费模式；然后判断受支持模式、会员、免费章节、整书商品和章节报价。`login_free` 表示登录后免费，不表示匿名可读。

### 7.3 章节正文

正文请求按以下顺序执行：

1. 校验章节 ID；
2. 验证章节启用及所属书籍发布状态；
3. 计算读者访问决策并拒绝不可读请求；
4. 读取当前对象引用；
5. 从 MinIO 读取并校验大小、SHA-256 和 UTF-8；
6. 规范化纯文本并计算前后启用章节；
7. 转换冻结 `ReaderChapterContent` DTO。

热点正文可缓存，但缓存值必须由 PostgreSQL 当前引用版本和对象哈希共同标识。切换正文版本后旧缓存不得继续返回。

## 8. 公开 SEO

M3 复用 M2 的 `novel_reader_seo_config(id=1)`，实现：

```text
GET /reader/seo/config
GET /reader/seo/robots.txt
GET /reader/seo/sitemap.xml
GET /reader/seo/sitemap-books-{page}.xml
```

配置接口使用 Reader JSON 包装。原始资源保持 UTF-8 文本或 XML、5 分钟公共缓存和基于完整响应体的 ETag。sitemap 每页上限固定为 `49,998`；开关、未启用收录、非法页码、单页和多页行为与冻结实现一致。原始资源不套 JSON。

## 9. 个人数据语义

- 书架添加重复请求返回现有关系，删除不存在关系保持冻结结果；
- 点赞切换与书籍 `like_count` 在同一 PostgreSQL 事务更新，并防止并发重复计数；
- 历史以读者和书籍为唯一键，只接受属于该书且可见的章节；位置类型、位置值和百分比按冻结边界校验；
- 偏好只接受主题 `cream/night/green`、阅读模式 `scroll/page` 及冻结类型中的缩进、字体等取值；缺失记录返回确定性默认值；
- 反馈只允许读者读取自己的记录，状态固定为 `pending/replied`，回复字段由后续管理能力维护；
- 所有写操作先提交 PostgreSQL，再失效 Redis；缓存失效失败不回滚已提交业务事务，但必须记录并允许 TTL 收敛。

## 10. 兼容响应与错误

JSON 成功响应固定为：

```json
{"code":200,"msg":"操作成功","data":{}}
```

分页成功响应固定为：

```json
{"code":200,"msg":"查询成功","rows":[],"total":0}
```

Reader 兼容响应器不得复用 GVA 管理端 `code=7`。冻结旧实现中的 JSON 业务失败主要保持 HTTP 200，并由业务码表达。已固化章节访问错误为：

| 业务码 | 消息 |
| --- | --- |
| `46101` | `请先登录后阅读` |
| `46102` | `仅限会员阅读` |
| `46103` | `请先购买作品` |
| `46104` | `请先购买章节` |
| `46105` | `作品收费模式不可用` |
| `46106` | M4 保留：整书报价变化为 `作品报价已变化，请确认新价格`，商品不可购买为 `作品暂不可购买` |

无效、伪造、过期、撤销或封禁读者身份返回 HTTP 200、`code=401`、`msg="认证失败，无法访问系统资源"`。不存在、已删除或未发布的书籍统一表现为“作品不可访问”，章节统一表现为“章节不可访问”，避免泄漏后台状态。

PostgreSQL、Redis 和 MinIO 错误映射为稳定兼容错误。正文对象缺失、大小不符、哈希不符和超时在内部分类记录，但对外不得暴露 SQL、连接地址、Bucket、对象键或堆栈。请求 ID 和追踪 ID 进入日志与响应头，不向冻结 JSON 增加字段。

`46106` 不由 M3 接口产生。它在本文中只用于锁定 M4 后续购买接口的冻结兼容语义，不能据此宣称 M3 已实现购买流程。

原始 SEO 资源保留真实 HTTP 语义：不可用页为 404，内部依赖不可用为 503。

## 11. 旧数据迁移

M3 在现有 `moonbook-legacy-migrate` 中按可恢复阶段迁移：

1. 读者账号与密码摘要；
2. 完成访问判断所需的商品、定价、会员和权益；
3. 书架与点赞；
4. 阅读历史与偏好；
5. 反馈。

主要来源包括 `reader_user`、历史 `user`、`reader_product`、`reader_entitlement`、`reader_membership_grant`、`reader_bookshelf`、`reader_book_like`、`reader_reading_history`、`reader_reading_preference`、`reader_feedback` 及经盘点确认仍有有效独有数据的历史对应表。

每个阶段必须：

- 强制源 MySQL 为 `read_only=1` 和 `super_read_only=1`；
- 按主键或稳定复合游标分批；
- 在目标写入事务中同步检查点；
- 保留旧 ID 并推进序列；
- 支持中断恢复和幂等重跑；
- 对坏关联、重复关系、未知枚举和摘要格式生成结构化错误；
- 不在日志或错误清单记录密码摘要全文、Token、反馈全文或正文；
- 不因单条坏数据静默丢弃，也不覆盖非 legacy 来源的目标记录。

钱包、流水、订单和支付不在这些阶段迁移。权益若引用尚未迁移的历史订单，保存脱敏旧引用和来源类型，待 M4 迁移订单后核对，不伪造订单记录。

## 12. 测试与验证

### 12.1 契约测试

为 M3 范围内每个冻结接口建立可执行测试，覆盖方法、路径、参数、Header、请求体、HTTP 状态、业务码、消息、包装、分页、日期、`null`、空数组、缺省字段和 Content-Type。测试必须包含 `9007199254740993` 与 `9223372036854775807` 字符串 ID。

`docs/contracts/reader-api.md` 为每项接口链接请求/响应快照与测试文件。尚属 M4 的接口继续明确标记所属阶段，不能用 M3 的只读模型冒充交易接口已经完成。

### 12.2 单元与集成

- 四种收费模式乘以匿名、普通、会员、整书权益和章节权益的决策矩阵；
- 旧摘要登录、错误密码、禁用账号、摘要升级和会话撤销；
- 书架、点赞、历史、偏好和反馈的约束、并发及隔离；
- 真实 PostgreSQL 的空库迁移、重跑、事务和约束；
- 真实 Redis 清空、缓存重建、限流和失效失败；
- 真实 MinIO 的正常正文、缺失、篡改、超时、大小及哈希失败；
- 真实只读 MySQL 到 PostgreSQL 的检查点、错误清单、幂等重跑和序列推进。

### 12.3 Reader 关键旅程

完整 Compose 栈运行冻结 `reader-ui`，验证：

- SSR 首页、书库、分类、书籍详情和 SEO；
- 注册、登录、退出、资料和改密；
- 免费、会员、整书权益和章节权益阅读；
- 书架、点赞、历史、偏好和反馈；
- Token 过期后的会话清理与登录流程；
- robots、sitemap 代理、超时和 404；
- 桌面与移动视口无 Reader 业务回归。

### 12.4 回归与安全

- Go 单元、集成、race 与 vet；
- 冻结 Reader 现有测试和生产构建；
- `reader-ui` Git 跟踪文件与冻结 commit 的 blob/path 零差异；
- PostgreSQL 迁移从零到最新且重复执行 `applied=0`；
- Gitleaks 无新增秘密；
- 临时应用和隔离容器清理，默认项目 PostgreSQL、Redis、MinIO 保持健康。

## 13. 实施切片

M3 按以下可独立提交的纵向切片实施，每个切片均包含迁移、服务、HTTP、旧数据转换和测试：

1. Reader 兼容响应、身份、密码升级与 Commerce 只读基础；
2. 公开分类、书目、章节、正文和 SEO；
3. 书架与点赞；
4. 阅读历史与偏好；
5. 反馈及所需管理能力；
6. 全部冻结 M3 契约、Reader E2E、迁移回归和退出审计。

后续实施计划可以按切片拆成多个计划文档，但不得改变本文的模块所有权、兼容契约或 M3/M4 边界。

## 14. 完成判据

M3 只有在以下条件全部满足并形成中文提交后才算完成：

- 读者账号、认证、书架、历史、偏好、点赞和反馈已实现并迁移；
- 公开书目、章节、正文和 SEO 契约已实现；
- 历史商品、定价、会员和权益可正确驱动章节访问；
- 管理员与读者身份隔离，旧 Token 失效和旧密码升级行为兼容；
- M3 范围内冻结接口的契约测试和关键旅程全部通过；
- PostgreSQL、Redis、MinIO 和只读 MySQL 的真实故障与迁移路径通过；
- Reader 跟踪文件与冻结 commit 零差异；
- Long ID 字符串和币值边界有自动化证据；
