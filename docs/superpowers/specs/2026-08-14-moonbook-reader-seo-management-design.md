# Moonbook 读者 SEO 管理设计

## 1. 文档状态

- 日期：2026-08-14
- 状态：设计已获用户确认，书面规格待复核
- 所属里程碑：M2 小说核心与对象存储
- 实现范围：读者 SEO 配置的 PostgreSQL 模型、管理 API、管理页面和旧数据迁移
- 延后范围：`/reader/seo/*` 公开兼容接口、`robots.txt` 与 sitemap 生成，统一在 M3 实现

本文是总体重构设计的补充规格。若本文与根目录 `AGENTS.md`、目标文档或总体设计冲突，以约束更严格者为准。

## 2. 背景与目标

冻结旧后台包含独立的“SEO 设置”页面，通过以下管理接口维护读者站点 SEO 配置：

```text
GET /novel/readerSeo/config
PUT /novel/readerSeo/config
```

旧配置保存在 `novel_reader_seo_config`，固定主键为 `1`。管理功能矩阵已将该能力标为待补。M2 必须完成配置管理和旧数据迁移，避免小说管理闭环遗留有效功能缺口；M3 的读者兼容层复用同一模型，不在 M2 提前引入公开路由。

本切片的完成目标是：管理员能够读取、校验和保存完整 SEO 配置；旧 MySQL 配置能够安全、幂等地迁移；无效旧配置不会污染新系统默认值或阻断其他迁移阶段。

## 3. 方案选择

采用独立的 `server/internal/modules/novel/readerseo` 模块。

未采用的方案：

- 并入 `books` 模块：文件较少，但 SEO 配置是站点级单例，不属于单本书籍生命周期，边界会混乱。
- 全部延后到 M3：可集中实现公开接口，但会让 M2 管理功能矩阵保留已确认缺口。

独立模块只依赖 PostgreSQL 和平台管理响应、鉴权及审计能力，不依赖 MinIO 或 Redis。M3 通过明确的查询服务读取配置，不能绕过模块直接操作表。

## 4. 数据模型

新增前向迁移 `00011_novel_reader_seo.sql`。迁移建立单行配置表，并初始化固定 `id = 1` 的默认记录。`00001` 至 `00010` 已执行，严禁修改、改名或删除。

配置字段如下：

| 字段 | PostgreSQL 类型 | 约束 |
| --- | --- | --- |
| `id` | `bigint` | 主键且只能为 `1` |
| `seo_enabled` | `boolean` | 非空，默认启用 |
| `indexing_enabled` | `boolean` | 非空，默认启用 |
| `sitemap_enabled` | `boolean` | 非空，默认启用 |
| `site_name` | `varchar(100)` | 非空、去除首尾空白后非空 |
| `site_url` | `varchar(2048)` | 非空，HTTP/HTTPS 站点根 URL |
| `default_description` | `varchar(2000)` | 非空、去除首尾空白后非空 |
| `home_title` | `varchar(500)` | 非空、去除首尾空白后非空 |
| `home_description` | `varchar(2000)` | 非空、去除首尾空白后非空 |
| `books_title_template` | `varchar(500)` | 非空，合法书库占位符 |
| `books_description_template` | `varchar(2000)` | 非空，合法书库占位符 |
| `book_title_template` | `varchar(500)` | 非空，合法书籍占位符 |
| `book_description_template` | `varchar(2000)` | 非空，合法书籍占位符 |
| `created_at` | `timestamptz` | 非空 |
| `updated_at` | `timestamptz` | 非空 |

默认值与冻结旧系统的正式默认配置一致。布尔值在 PostgreSQL 内使用 `boolean`，管理 DTO 使用 JSON `boolean`；旧 MySQL 的 `0/1` 仅在迁移边界转换。配置 ID 面向 JavaScript 时必须输出字符串 `"1"`。

迁移同时注册：

- “SEO 设置”管理菜单；
- GET 与 PUT 两条 API 元数据；
- 超级管理员 Casbin 策略；
- 页面所需权限标识。

数据库约束负责固定单例主键、字段长度和非空等基础不变量；URL 和模板语义由服务层校验。更新使用单行事务锁和固定主键更新，不允许创建第二条配置。

## 5. 校验规则

### 5.1 站点 URL

`siteUrl` 必须满足：

- 协议只能是 `http` 或 `https`；
- 必须包含有效主机名；
- 不得包含用户名或密码；
- 不得包含 query 或 fragment；
- 路径只能为空或 `/`；
- 保存时规范化为不带结尾 `/` 的根 URL。

### 5.2 模板占位符

书库标题和描述允许：

```text
siteName, keyword, categoryName, subCategoryName
```

书籍标题和描述允许：

```text
siteName, bookName, authorName, categoryName, bookDesc
```

占位符语法固定为 `{name}`，名称大小写敏感。未知占位符、未闭合花括号、孤立花括号均拒绝保存。普通文本可以包含标点和 UTF-8 字符。

### 5.3 字符串与开关

所有必填文本去除首尾空白后必须非空，规范化后的值再执行字符长度校验。服务端是最终校验边界，不能依赖管理前端校验保证数据正确性。

## 6. 管理 API

沿用冻结后台路径并挂载到 GVA 私有路由组：

```text
GET /novel/readerSeo/config
PUT /novel/readerSeo/config
```

GET 返回固定配置。若数据库因异常缺少 `id = 1`，服务端返回可追踪的内部错误，不在读取路径静默重建数据。

PUT 接收除 `id`、创建时间和更新时间外的全部可编辑字段。处理流程：

1. 绑定并校验请求；
2. 开启 PostgreSQL 事务并锁定 `id = 1`；
3. 更新完整配置和 `updated_at`；
4. 提交事务；
5. 返回更新后的配置。

读取和保存使用现有 Moonbook 管理响应适配器，不向模块引入 GVA 内部模型依赖。未认证请求返回管理基座既有未认证语义；无权限请求由 Casbin 拒绝；PUT 纳入 GVA 操作审计。错误响应不得泄漏 SQL、连接信息或内部表名。

## 7. 管理前端

新增独立 API 文件、类型定义和 `web/src/view/novel/readerSeo/index.vue` 页面。页面按当前 GVA Vue 与 Element Plus 约定实现，保持旧功能等价而不复制旧页面代码。

页面分为三个未嵌套的内容区：

- 基础设置：SEO 开关、站点名称、站点 URL 和默认描述；
- 页面文案：首页字段、书库模板、书籍模板及即时预览；
- 收录控制：索引和 sitemap 开关。

使用开关处理布尔值，文本输入遵守数据库长度，保存按钮受权限控制并提供加载、保存中、成功和失败状态。模板预览仅用于帮助管理员检查效果，不改变提交内容。前端复用与服务端相同的占位符集合和 URL 规则以提供即时反馈，但服务端仍重复完整校验。

配置 ID 的 TypeScript 类型为 `string`。页面不得使用 `Number`、`parseInt`、`el-input-number` 或算术方式处理 ID。

## 8. 旧数据迁移

新增 CLI 阶段：

```text
moonbook-legacy-migrate novel-reader-seo
```

阶段只读访问旧 MySQL 的 `novel_reader_seo_config`，只接受固定主键 `1`。迁移保留 `id` 和可用的创建、更新时间，将 `0/1` 转为 PostgreSQL 布尔值，并执行与在线保存完全一致的 URL、模板、必填和长度校验。

迁移策略采用已确认的容错方案：

- 旧表不存在：保留 PostgreSQL 默认记录，写入明确错误项，阶段可完成；
- 缺少 `id = 1`：保留默认记录，写入明确错误项，阶段可完成；
- 存在额外 ID：不迁移额外记录，逐条写入错误清单；
- `id = 1` 任一字段无效：整条配置不写入，保留默认记录并写入字段级错误；
- 配置有效：在 PostgreSQL 事务中完整覆盖固定记录；
- 重跑：相同源数据得到相同目标状态，不新增记录，不重复产生不可控副作用。

错误清单不得包含数据库凭据或未经截断的异常长文本。检查点和结果统计沿用现有业务迁移框架。SEO 阶段的容错只适用于本站点配置，不能弱化其他阶段的完整性要求。

## 9. M3 接口边界

M2 不注册任何 `/reader/seo/*` 路由，也不生成 robots 或 sitemap。M3 应复用本模块提供的只读查询接口，并分别实现：

- `GET /reader/seo/config` 兼容响应；
- robots 规则；
- sitemap 索引和内容路由；
- SEO、索引、sitemap 三个开关的组合行为；
- 冻结 `reader-ui` SSR 与浏览器契约测试。

公开响应不得直接暴露管理 DTO、数据库字段名或管理审计信息。

## 10. 错误处理与可观测性

- 请求校验错误返回稳定的管理端参数错误，不进入数据库事务；
- 配置缺失、数据库失败和审计失败记录结构化日志与追踪 ID；
- 日志记录字段名和错误类别，不记录完整配置正文；
- 迁移报告区分源缺失、主键异常、字段无效、目标写入失败和检查点失败；
- 指标沿用 HTTP、数据库和迁移框架现有指标，不为单例配置引入 Redis 缓存或独立 Worker。
