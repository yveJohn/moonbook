# 管理端充值订单展示优化实施计划

## 1. 约束

- 依据 `docs/superpowers/specs/2026-08-29-moonbook-admin-recharge-order-display-design.md` 实施。
- 只修改管理前端充值订单页面，不修改管理 API、Reader 接口、数据库或支付业务逻辑。
- 订单及读者 Long ID 继续按字符串处理。

## 2. 实施任务

### 任务一：固定页面展示契约

- [ ] 扩展充值订单页面源码级测试，锁定默认每页 10 条。
- [ ] 锁定八种英文状态值与中文标签、三处统一中文展示和未知状态回退。
- [ ] 锁定创建时间使用现有日期格式化工具且空值显示 `-`。

### 任务二：优化充值订单页面

- [ ] 把默认 `pageSize` 从 20 调整为 10。
- [ ] 使用统一状态选项驱动筛选，并让列表和详情调用同一显示函数。
- [ ] 格式化列表创建时间，不改写接口响应数据。

### 任务三：验证与记录

- [ ] 运行充值订单定向测试和管理前端完整测试。
- [ ] 运行 ESLint、生产构建和供应链检查。
- [ ] 更新 `docs/progress/refactor-status.md` 并按逻辑使用简体中文提交。

## 3. 服务影响

- 代码只影响管理前端 Web 服务。
- 本地或部署环境应用变更时需要重新构建并重启 Web 服务。
- Server、Reader、PostgreSQL、Redis 和 MinIO 无需重启。
