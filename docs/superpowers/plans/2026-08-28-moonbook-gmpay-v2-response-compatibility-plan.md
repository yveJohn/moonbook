# Moonbook GM Pay v2 创建响应兼容与诊断实施计划

## 1. 约束

- 依据 `docs/superpowers/specs/2026-08-28-moonbook-gmpay-v2-response-compatibility-design.md` 实施。
- 只对 `currency=USD` 和 `token=USDT` 放宽大小写，不放宽订单号、金额、状态、地址、过期时间和支付链接校验。
- 字段级诊断不得保存或返回原始响应、签名、PID、Secret 或其他敏感值。
- `gateway_unknown` 仍表示创建结果不确定，不自动重试网关创建请求。
- 不修改冻结的 `reader-ui`，不新增 PostgreSQL 迁移，不执行真实支付或生产写入。

## 2. 实施任务

### 任务一：GM Pay v2 响应兼容与字段级诊断

- [ ] 先更新客户端测试，以 GM Pay v2 实际的 `USD/USDT` 响应证明当前失败。
- [ ] 为成功响应字段校验引入稳定、脱敏的字段级失败码。
- [ ] 使用大小写不敏感比较接受 `USD/USDT`，保持返回值和其余字段校验边界明确。
- [ ] 覆盖合法大小写组合、错误币种、错误 Token 和其余关键字段失败码。
- [ ] 验证错误摘要不泄漏响应值或配置秘密。

### 任务二：过期诊断保留

- [ ] 调整批量和惰性过期共用 SQL：已有失败码与原因时保留，没有时写入 `ORDER_EXPIRED`。
- [ ] 扩展真实 PostgreSQL 集成测试，覆盖 `gateway_unknown` 原始诊断保留和普通过期默认诊断。

### 任务三：管理订单可见性

- [ ] 扩展管理订单领域类型和查询，读取 `failure_code`、`failure_message`。
- [ ] 管理 API 以 `failureCode`、`failureMessage` 返回字段，保持 Long ID 字符串合同。
- [ ] 管理订单详情只读展示失败码和失败原因。
- [ ] 补充后端 HTTP 合同测试和管理前端组件测试。

### 任务四：验证与收尾

- [ ] 执行支付客户端 Go 单元测试。
- [ ] 使用项目专用真实 PostgreSQL 执行充值过期与管理订单集成测试。
- [ ] 执行相关 Go 测试、`go vet` 和格式检查。
- [ ] 执行管理前端定向测试、静态检查和生产构建。
- [ ] 更新 `docs/progress/refactor-status.md`，记录生产根因、实现和验证证据。
- [ ] 检查全部已跟踪和未跟踪修改、秘密、`git diff --check` 与暂存区内容。
- [ ] 按后端兼容修复、管理可见性及进度证据的逻辑关系使用简体中文提交，并确认工作区干净。

## 3. 完成标准

- GM Pay v2 返回 `USD/USDT` 时，Moonbook 保存网关交易号、实际金额、收款地址、支付链接和过期时间，订单进入 `pending`。
- 不受支持的币种、Token 或其他响应字段仍被拒绝，并产生可定位的稳定失败码。
- 订单过期不会抹除已有的创建失败诊断。
- 管理订单详情能查看失败码和失败原因，Reader 无需修改即可显示成功订单二维码。
- 相关单元、集成、合同、前端测试、静态检查和构建全部通过。

## 4. 服务影响

- `server`：需要重新构建并重启。
- `web`：需要重新构建并发布。
- `reader-ui`、EPUSDT、PostgreSQL、Redis 和 MinIO：无代码、结构或配置变更，无需因本次修复重启。
