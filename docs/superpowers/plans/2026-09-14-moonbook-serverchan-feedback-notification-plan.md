# Moonbook 用户反馈 Server酱通知实施计划

## 1. 约束

- 依据 `docs/superpowers/specs/2026-09-14-moonbook-serverchan-feedback-notification-design.md` 实施。
- 反馈必须先成功写入 PostgreSQL，再尝试通知；通知失败不得改变读者接口成功结果。
- SendKey 只能通过参数管理维护，使用 `MOONBOOK_APP_MASTER_KEY` 和统一 `secretcrypto` 加密。
- 参数查询接口不得返回 SendKey 明文或密文，日志不得包含 SendKey、完整请求 URL或反馈全文。
- Server酱目标固定为官方 HTTPS 地址，不允许通过参数覆盖。
- 不修改冻结版 `reader-ui`，不增加测试通知入口、自动重试、Outbox 或通知历史。
- 不连接生产环境，不执行真实生产通知，不 `git push`。

## 2. 实施任务

### 任务一：系统参数敏感值保护

- [ ] 确认当前最高 PostgreSQL 迁移版本，新增更高版本迁移，为未删除的 `serverchan.enabled` 和 `serverchan.send_key` 建立局部唯一约束。
- [ ] 更新迁移 manifest 和迁移契约测试，验证空库、升级及重复执行路径。
- [ ] 在系统参数服务中定义保留键、掩码和稳定的 `secretcrypto.Scope`。
- [ ] 创建 SendKey 时校验非空值，通过统一主密钥加密后再写入 `sys_params.value`。
- [ ] 更新 SendKey 时支持掩码保留原值和新明文重新加密；限制保留键改名及普通参数改为保留键。
- [ ] 严格校验 `serverchan.enabled` 只能为 `true` 或 `false`。
- [ ] 对参数列表、详情和按键查询结果统一掩码 SendKey。
- [ ] 添加服务测试，覆盖加密、掩码、保留、轮换、非法开关、改名和重复键。
- [ ] 格式化并执行参数服务及迁移定向测试。
- [ ] 提交：`保护Server酱参数密钥`。

### 任务二：Server酱通知组件

- [ ] 新增 `internal/platform/serverchan` 包，定义反馈通知输入、配置仓储和 HTTP 客户端边界。
- [ ] 从 `sys_params` 实时读取开关及加密 SendKey；关闭时正常跳过，启用但配置异常时返回归一化错误。
- [ ] 校验 SendKey 字符集和长度，通过固定 `https://sctapi.ftqq.com/{sendKey}.send` 地址发送表单请求。
- [ ] 使用 3 秒总超时、限制响应体大小，并校验 HTTP 状态和 Server酱业务码。
- [ ] 将传输层错误归一化，确保返回错误不携带包含 SendKey 的 URL或响应原文。
- [ ] 生成 Markdown 正文，包含字符串 ID、提交时间和最多 1,000 个 Unicode 字符的反馈内容。
- [ ] 添加配置仓储与 HTTP 客户端测试，覆盖关闭、缺失、解密失败、路径、表单、截断、业务失败、非法响应、超时和秘密不泄漏。
- [ ] 格式化并执行通知组件测试。
- [ ] 提交：`实现Server酱反馈通知组件`。

### 任务三：反馈接入与综合验证

- [ ] 为读者个人服务增加窄通知接口和可选装配，不让读者域依赖 Server酱协议。
- [ ] 反馈写入成功后使用脱离请求取消信号、但受 3 秒上限约束的上下文调用通知器。
- [ ] 通知失败只写脱敏结构化警告日志，返回已创建反馈；反馈写入失败时不得通知。
- [ ] 在业务路由初始化时装配 Server酱配置仓储、HTTP 客户端和统一加密服务。
- [ ] 添加服务测试，覆盖调用一次、不调用和失败不回滚；保持现有反馈 HTTP 契约快照不变。
- [ ] 更新 `docs/progress/refactor-status.md`，记录功能、配置方法、验证证据和服务影响。
- [ ] 执行相关 Go 单元/集成测试、反馈契约测试、`go vet`、后端构建、迁移验证和秘密扫描。
- [ ] 检查全部已跟踪及未跟踪文件，执行 `git diff --check` 和 `git diff --cached --check`。
- [ ] 提交：`接入用户反馈Server酱通知`。

## 3. 完成标准

- 管理员可通过参数管理保存开关和 SendKey，数据库中 SendKey 为统一加密信封。
- 任一参数查询响应都只显示 `********`，更新掩码不会覆盖原密文。
- 新反馈落库后最多发起一次 Server酱请求，通知正文包含正确字符串 ID、时间和受限内容。
- 配置关闭时不发送；配置或外部服务异常时反馈接口仍按原契约成功返回。
- 请求、响应、日志和测试输出均不泄漏 SendKey 或完整反馈正文。
- PostgreSQL 迁移、后端测试、静态检查与构建通过，工作区无有效未提交修改。

## 4. 服务影响

- `server`：需要重新构建并重启，以加载参数保护和反馈通知代码。
- PostgreSQL：新增仅针对两个 Server酱保留参数键的局部唯一索引，不修改现有业务数据。
- `web`：复用现有参数管理页面，无代码变更，无需因本功能单独重启；若与后端一起发布静态资源也不需要额外配置。
- `reader-ui`、Redis 和 MinIO：无代码或配置变更，无需重启。
- 参数在后端请求时实时读取，后续开关或 SendKey 调整无需重启服务。
