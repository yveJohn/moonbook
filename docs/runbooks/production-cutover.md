# 生产切换与 Go/No-Go Runbook

本文件是生产切换准备材料，不是生产执行授权。目标完成后仍需用户明确批准停机、迁移、DNS/反向代理变更和真实支付环境操作。

## 切换前准备

- 冻结旧系统发布，确认旧仓库冻结 commit、GVA 基线 commit、新仓库 commit 和迁移工具版本。
- 使用脱敏或受控生产副本完成全量迁移演练，证明预计停机窗口小于 12 小时，并保留核对报告。
- 完成 PostgreSQL/MinIO 协调备份，备份校验清单通过，恢复演练成功。
- 确认管理功能矩阵无缺项；Reader 原样代码差异为零；Reader 契约、SSR、浏览器关键旅程、财务核对和安全扫描均有报告。
- 准备独立 Compose 项目、PostgreSQL/MinIO 卷、Secret、TLS、监控告警和回退窗口。禁止将凭据写入命令历史、日志或 Git。
- 以 `scripts/verify-m6-full-copy.sh --preflight` 固定备份绝对路径、SHA-256、隔离项目和工作目录；完整演练报告必须来自同一 commit。生产环境不得直接运行该本地演练脚本。
- 若旧库存在 `novel_txt_import_task`，逐任务核对外部 TXT 原文件清单；任务存在但原文件、大小或 SHA-256 无法证明时立即 No-Go。

## Go/No-Go 门

任何一项为 No-Go 都不得停机：

| 检查项 | Go 证据 |
| --- | --- |
| 备份 | PostgreSQL dump、MinIO 对象清单和 SHA-256 清单可恢复 |
| 迁移 | 完整副本恢复成功，只读 MySQL 预检通过，全部 checkpoint 完成、迁移错误为零，幂等重跑稳定 |
| 应用 | Compose 健康检查、管理登录、Reader 关键旅程和 MinIO 正文读取通过 |
| 数据 | 行数、主键、关联、对象数量/字节数、订单/钱包/权益无差异 |
| 时间 | 完整副本实测总耗时低于 12 小时，且为核对、冒烟、观察与回退保留已批准余量 |
| 运维 | 监控、告警、日志、Worker 恢复和回退 Runbook 已演练 |
| 外部依赖 | 支付、邮件、AI、采集代理在受控替身或真实授权环境通过 |
| 回退 | 已计算最晚回退时间，旧系统仍可启动，回退数据处置已获批准 |

## 停机窗口顺序

1. 宣布维护并停止写入；保留旧系统只读观察窗口。
2. 创建最终 PostgreSQL/MinIO 备份并校验；记录源库只读状态和起始计数。
3. 在目标环境运行只读预检和全部迁移 stage；每批保留 checkpoint，错误进入清单。
4. 执行行数、主键、关联、对象哈希、财务和关键业务核对；任一失败立即进入 No-Go/回退评估。
5. 启动新 Compose，执行 readiness、管理、Reader、Worker、支付回调替身和监控冒烟。
6. 先切换内部验证入口，再由授权人员修改反向代理/DNS；保留旧入口和回退时间。
7. 观察错误率、延迟、任务队列、数据库连接、对象读取和财务指标；达到批准观察时长后再宣布完成。

## 最晚回退时间

`最晚回退时间 = 维护窗口结束时间 - 回退耗时 - 数据核对耗时 - 安全余量`。

回退前必须停止新系统写入并保存新系统期间产生的订单、流水、权益和任务差异；禁止通过直接改表“回写”旧库。具体数据处置按 `rollback.md` 执行并由用户批准。
