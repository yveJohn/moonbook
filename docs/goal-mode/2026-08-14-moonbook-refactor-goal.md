## 2. 可直接使用的目标描述

> 在 `/Users/yve/code/ai-project/moonbook` 中完成 Moonbook 管理后台、管理前端和读者兼容后端的全量重构，使项目达到可执行生产停机迁移和切换的就绪状态。
>
> 必须严格遵守根目录 `AGENTS.md` 和 `docs/superpowers/specs/2026-08-14-moonbook-gin-vue-admin-refactor-design.md`。旧项目 `/Users/yve/Documents/moonbook` 仅作为冻结的功能、接口和数据迁移来源，禁止修改。
>
> 基于实施开始时 Gin-Vue-Admin 官方仓库 `main` 的实际 commit，记录并永久锁定该 commit，同时保留当前仓库既有设计提交历史。采用 Go 模块化单体、Gin-Vue-Admin 管理前端、PostgreSQL、Redis、MinIO 和 Docker Compose。允许直接在本地 Docker 启停本项目专用 PostgreSQL、Redis、MinIO，用于开发、集成测试和迁移演练。
>
> 完整迁移当前管理后台全部有效业务能力。将冻结版 `reader-ui` 原样迁入新仓库，并保证其业务代码零修改接入新 Go 后端。所有旧业务 ID 原值保留，所有面向 JavaScript 的 Long/雪花 ID 必须输出并按字符串处理。章节正文及所有非结构化文件存 MinIO，PostgreSQL 保存结构化事实和对象引用，Redis 不承载唯一业务事实。
>
> 按本文件里程碑纵向实施。每个业务域同时完成后端、管理页面、数据库迁移、旧数据映射和自动化测试；每个逻辑单元验证后用简体中文提交。持续维护进度文档和完成证据。普通技术问题自行解决，不要在骨架或部分功能阶段停止。
>
> 目标终点是：全部代码、测试、Docker Compose、迁移工具、自动校验、生产数据副本演练流程、备份恢复流程、监控和切换/回退 Runbook 完成，冻结版 reader-ui 契约和关键旅程通过，管理功能矩阵无缺项，项目达到生产切换就绪。未经用户另行明确授权，不得连接或修改生产环境，也不得执行正式生产迁移、DNS/反向代理切流、真实支付操作或 git push。

## 3. 目标边界

### 3.1 目标内

- 导入并锁定 Gin-Vue-Admin 基线；
- 原样迁入冻结版 `reader-ui`；
- 完整重构管理后端和管理前端；
- 实现当前 `reader-ui` 实际调用的全部兼容 API；
- 设计并实现新的 PostgreSQL 数据模型；
- 使用 Redis 实现缓存、限流、短期会话和任务协调；
- 使用 MinIO 存储章节正文、封面、导入导出文件和附件；
- 实现当前有效的支付、AI、邮件、采集代理等第三方适配器；
- 实现旧 MySQL 到 PostgreSQL/MinIO 的全量迁移工具；
- 建立 Docker Compose、本地开发、CI、监控、备份恢复和运维文档；
- 完成自动化测试、迁移演练能力和生产切换 Runbook。

### 3.2 目标外

- 实际生产停机、生产数据迁移和流量切换；
- 生产 DNS、反向代理、数据库、Redis、MinIO 和支付环境变更；
- k3s 部署清单和生产集群高可用建设；
- 微服务拆分；
- 当前冻结版 `reader-ui` 未调用的历史接口；
- 已废弃或未启用的第三方集成；
- 切换验收前的读者端新功能或 UI 重构。

目标外事项不能阻止目标内工作继续。实际生产切换将在本目标完成并经用户审阅证据后单独授权。

## 4. 自主执行方式

目标模式应按以下循环持续工作：

1. 读取 `AGENTS.md`、设计文档、进度文档和当前 Git 状态；
2. 选择当前里程碑中最靠前的未完成纵向功能；
3. 先从旧代码和测试提取事实，再做实现；
4. 同时完成数据模型、后端、管理页面、迁移映射和测试；
5. 使用本地 Docker 基础设施执行真实集成验证；
6. 更新进度与完成证据；
7. 检查所有工作区修改，按功能使用简体中文提交；
8. 继续下一个未完成项，直到全部完成判据满足。

每一轮都应复用已有成果。不得反复重新脚手架、改写已验证模块，或因为上下文切换而从头开始。

## 5. 里程碑与退出条件

### M0：冻结、基线与盘点

交付物：

- 旧仓库冻结 commit 记录；
- Gin-Vue-Admin 官方 URL、branch、完整 commit hash 和导入方式记录；
- 原样迁入的 `reader-ui` 及源/目标差异校验结果；
- 管理后台完整功能矩阵；
- 读者 API 契约清单；
- 旧 MySQL 表、文件、第三方集成和约 8 GB 备份的容量盘点工具；
- `docs/progress/refactor-status.md`。

退出条件：基线可追溯，功能与数据范围无未解释缺口，冻结版 `reader-ui` 的现有测试基线已记录。

### M1：工程与本地基础设施

交付物：

- 模块化单体目录和依赖规则；
- PostgreSQL、Redis、MinIO、反向代理的 Docker Compose；
- `.env.example`、本地初始化、健康检查和优雅停机；
- 版本化 PostgreSQL 迁移框架；
- 结构化日志、追踪 ID、指标和错误规范；
- 持久化任务框架和业务迁移工具骨架；
- CI 和一键验证入口。

退出条件：空环境可按文档启动，数据库可从零迁移，真实 PostgreSQL/Redis/MinIO 集成测试通过，仓库无秘密。

### M2：小说核心与对象存储

交付物：

- 分类、作者、书籍、章节、标签、发布状态和相关管理能力；
- MinIO 章节正文、封面、文件服务；
- 版本化对象键、SHA-256、引用切换、孤立对象回收和软删除；
- 对应管理页面、权限、API、迁移映射和测试。

退出条件：完整小说管理闭环通过；PostgreSQL 不会引用未成功上传对象；旧 ID 和前端字符串 ID 规则经边界测试证明。

### M3：读者域与零修改兼容

交付物：

- 读者注册登录、账号状态、书架、阅读历史、偏好、点赞和反馈；
- 旧密码摘要兼容与首次登录升级；
- 独立兼容路由、DTO、响应和错误映射；
- 所有冻结接口的可执行契约测试；
- SSR 和浏览器关键旅程测试。

退出条件：冻结版 `reader-ui` 业务代码无差异，现有测试、契约测试和关键旅程全部通过；旧 Token 失效场景行为兼容。

### M4：交易、支付与运营

交付物：

- 钱包、不可变流水、奖励、签到、邀请、会员、权益和订单；
- 充值产品、支付配置、回调验签、防重放和幂等；
- 读者运营、配置和统计管理页面；
- 财务迁移映射、核对器和测试。

退出条件：余额可由流水核对，订单/支付/权益状态机覆盖成功、失败、重复回调和并发场景，财务核对零差异。

### M5：内容生产与长任务

交付物：

- 论坛采集、来源与板块、候选和导入任务；
- TXT 导入、失败文件修复、书籍合并；
- AI 配置、模型、书籍画像、章节清洗、摘要和重试；
- 持久化状态机、租约、幂等、有限重试、恢复和人工重跑；
- 完整管理页面、迁移映射和测试。

退出条件：应用重启后任务可安全恢复；重复执行不产生重复业务结果；当前有效第三方集成具备本地替身或沙箱验证证据。

### M6：全量迁移与校验

交付物：

- 只读 MySQL 分批读取；
- 全业务数据和 MinIO 对象迁移；
- 检查点、中断恢复、幂等重跑和错误清单；
- 行数、主键、关联、枚举、财务、对象数量、字节数和哈希校验；
- 容量与耗时报告；
- 可重复的生产数据副本演练命令和报告模板。

退出条件：至少用完整可用的数据副本完成一次全量演练；没有静默丢弃；财务零差异；关键对象无缺失；预计正式执行稳定低于 12 小时并保留安全余量。若当前工作区没有生产数据副本，应完成工具和演练流程，并把该项明确标为需要用户提供副本后才能最终关闭的外部验收项。

### M7：生产切换就绪验收

交付物：

- 管理功能矩阵最终结果；
- 单元、集成、契约、E2E、性能和安全报告；
- PostgreSQL 与 MinIO 协调备份和恢复演练报告；
- Docker Compose 部署与升级文档；
- 监控、告警、故障处理和任务恢复文档；
- 12 小时停机迁移 Runbook；
- Go/No-Go 清单、最晚回退时间计算方法和回退 Runbook；
- 已知限制与真实第三方环境待验项。

退出条件：所有目标内完成判据都有可定位证据，工作区无有效未提交修改，仓库可由另一名工程师按文档复现。此时只能声明“生产切换就绪”，不能声明“生产切换完成”。

## 6. 完成判据

只有同时满足以下条件，目标模式才能将目标标记为完成：

- M0 至 M7 的所有目标内交付物已经实现并提交；
- 当前管理后台全部有效能力在新系统功能矩阵中无缺项；
- 冻结版 `reader-ui` 原样迁入且业务代码零差异；
- 读者兼容契约、SSR 和关键用户旅程全部通过；
- PostgreSQL 迁移可从空库完整执行；
- Redis 不保存唯一业务事实，缓存可以重建；
- 章节正文及其他文件通过 MinIO 大小和哈希校验；
- 旧业务 ID 全量保留，JavaScript ID 字符串规则有自动化边界测试；
- 钱包、流水、订单、支付和权益核对零差异；
- 长任务支持持久化、恢复、幂等、有限重试和人工处理；
- 本地 Docker Compose、测试、构建和验证入口可重复执行；
- 没有密钥、密码、Token 或敏感生产数据进入 Git；
- 备份恢复、迁移演练和切换回退材料完整；
- 所有有效修改按功能使用简体中文提交；
- `git status` 除明确忽略内容外干净；
- 最终报告明确服务影响、需重启服务、验证证据、提交列表和仍需用户执行的生产动作。

缺少生产凭据、真实支付环境或生产切换授权不影响其余目标继续推进。若唯一剩余项确实只能由用户或生产环境完成，目标模式必须列出精确命令、输入、期望输出、风险和验收方法，不得伪造成功结果。

## 8. 允许自主决策的事项

目标模式可在不改变批准设计的前提下自行决定：

- Go 包、模块和接口的具体命名；
- PostgreSQL 表名、索引、约束和版本迁移编号；
- Redis Key 命名与 TTL；
- MinIO Bucket 划分和非章节对象键；
- 测试框架、容器测试工具和 CI 组织；
- 批量迁移大小、并发和退避参数；
- 管理页面的具体布局与组件组合；
- 日志、指标和追踪库；
- 在固定 GVA 基线内符合现有约定的实现细节。

这些决策必须有测试或测量依据，并记录重要权衡。不得借“自主决策”改变完整迁移、读者零修改、旧 ID 保留、MinIO 正文存储、模块化单体或停机迁移等已批准约束。

## 9. 必须请求用户决策的事项

- 需要修改已批准业务范围或兼容契约；
- 安全要求与旧接口行为无法同时满足；
- 需要真实第三方密钥、支付商户操作或生产账号；
- 需要连接、写入或删除生产数据；
- 需要正式 DNS、反向代理或流量切换；
- 需要执行不可恢复或高风险数据操作；
- 发现无法判断用途或可能包含敏感信息的用户文件；
- 实际生产数据揭示财务差异或无法自动转换的业务歧义。

提出问题前，应完成所有安全且不依赖该答案的工作，并提供已查证事实、影响和推荐方案。
